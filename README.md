# Классификация типов обращений в IT-поддержку

## Описание задачи
Разработка ML-модели для автоматической маршрутизации обращений в службу IT-поддержки. На вход поступает текст тикета (тема + описание), на выходе — предсказанный отдел (queue). 

**Датасет:** Customer IT Support - Ticket Dataset (Kaggle). Использовано ~16 300 записей на английском языке (из 28 587).
**Целевая переменная:** `queue` (10 классов: Technical Support, Billing, IT Support и др.).

## Результаты
В ходе проекта было проведено 5 экспериментов. Лучшей моделью признан **LinearSVC** с предварительной очисткой текста и балансировкой классов (`class_weight='balanced'`).
*   **Accuracy:** 0.67
*   **Macro F1:** 0.68 (метрика выбрана из-за сильного дисбаланса классов в датасете).

## Архитектура
1. Клиент (тикет-система) отправляет POST-запрос на `/v1/predict`.
2. FastAPI валидирует данные через Pydantic.
3. ML-модель (TF-IDF + LinearSVC) делает предсказание.
4. Тикет-система получает JSON с названием отдела и автоматически маршрутизирует заявку.
5. **Веб-интерфейс:** FastAPI также отдает встроенную HTML-страницу (по корневому адресу `/`), которая служит для наглядной демонстрации. Пользователь вводит текст, нажимает кнопку, и система имитирует открытие чата с нужным отделом поддержки.

## API-контракт
**Метод:** `POST /v1/predict`

**Пример запроса:**
```json
{
  "subject": "Ошибка при оплате",
  "description": "Карта отклонена, хотя на счету есть деньги."
}
```

**Пример успешного ответа (200 OK):**
```json
{
  "queue": "Billing and Payments",
  "model_version": "v1.0"
}
```
*Коды ошибок:* 422 (пустой текст или отсутствие поля), 500 (ошибка сервера).

## Инструкция по запуску (локально)
1. Установите зависимости:
```bash
pip install -r requirements.txt
```
2. Обучите модель:
```bash
python src/train_models.py
```
3. Запустите сервер:
```bash
uvicorn src.api:app --reload
```
4. Документация API (Swagger) доступна по адресу: `http://127.0.0.1:8000/docs`
5. **Веб-интерфейс для демонстрации** доступен по адресу: `http://127.0.0.1:8000/`

## Запуск через Docker
```bash
docker build -t ticket-classifier .
docker run -p 8000:8000 ticket-classifier
```

## Тестирование
Запуск тестов осуществляется командой:

## Использование ИИ-ассистента
ИИ-ассистент использовался для генерации первых черновиков кода и документации. Весь сгенерированный код был проверен, запущен и отлажен командой. В процессе работы были выявлены и исправлены следующие недочеты:
1. ИИ не добавил проверку на пустые строки (состоящие из пробелов) в валидацию API — исправлено вручную.
2. В коде обучения нейросети BERT использовался устаревший параметр `logging_dir` (вызывал ошибку) — заменен на `eval_strategy`.
3. Предложенные ИИ символьные n-граммы снизили качество модели (F1 упал с 0.68 до 0.66) — усложнение отклонено.
4. **Разработка веб-интерфейса:** HTML/CSS/JS код для красивого сайта с имитацией чата был сгенерирован ИИ-ассистентом. Команда интегрировала его в FastAPI, проверила работу сценариев (успешная маршрутизация и обработка ошибок) и адаптировала дизайн под нужды демонстрации.

## Ограничения решения
1. Модель понимает только английский язык.
2. Модель часто путает семантически близкие отделы (Technical Support, IT Support, Product Support) из-за синтетической природы данных. В будущем планируется внедрить иерархическую классификацию или human-in-the-loop (ручную проверку при низкой уверенности модели).
